# 功能路线图(Roadmap)

> 创建日期:2026-10-10
> 定位:GrapeMobile 用于 **Android 自动化测试**(当前仅 Android)。
> 配套文档:待修复问题见 [CODE_REVIEW.md](CODE_REVIEW.md)。
> 维护约定:新功能按 `RM-NN` 顺延编号追加;完成后把状态改为 `DONE` 并在末尾「更新记录」追加一行。

## 1. 核心判断

目前工具**有执行,没有验证**:只有 tap / input / app_* / keyevent 六种步骤,只能"回放",还不能算"测试"。
下一阶段的目标是补齐测试的最小闭环:**操作 -> 断言 -> 失败诊断 -> 报告**。

建议先完成 [CODE_REVIEW.md](CODE_REVIEW.md) 中的 CR-01、CR-02(配置与格子尺寸),再开始 RM-01 至 RM-03。

### RM-01 断言步骤 (P0)

**目标**:让用例能判断"结果对不对",而不只是"点完了"。

**建议方案**
- 在 `src/steps.py` 新增步骤类型:`assert_exists`、`assert_not_exists`、`assert_text`。
- 画面存在性复用现有 `screen_similarity` 与步骤锚点图;文本断言复用 `locate/ocr.py`(rapidocr)。
- 支持超时轮询(与现有"等待锚点"机制一致):在 N 秒内满足即通过,超时即失败。
- 断言失败要抛出专门异常,供 RM-03 捕获并生成诊断。
- GUI 编排 Tab 增加对应的步骤卡片类型。

**验收**:一个用例中可写"点击登录后,断言出现'欢迎'文本",失败时整条用例标记为失败。

### RM-02 滑动、长按、双击 (P0)

**目标**:覆盖列表页、游戏手势等常见操作。

**建议方案**
- `AdbClient` 新增 `swipe(x1, y1, x2, y2, duration)`、`long_press(x, y, duration)`(用 `input swipe` 同点起止实现)、`double_tap`。
- `steps.py` 新增 `swipe` / `long_press` / `double_tap` 步骤类型,坐标沿用"格子编号"体系,起止点各填一个格子。
- `replay_render.py` 补滑动轨迹的动画渲染。
- 补单元测试(假客户端)。

**验收**:可录制并回放一次"从格子 A 滑到格子 B"。

### RM-03 失败诊断 (P0)

**目标**:用例失败时能一眼看出原因。

**建议方案**
- 步骤失败时自动保存:当前截图、期望锚点图、相似度数值、步骤序号与参数。
- 同时抓取 `adb logcat -d`(最近 N 行)与当前前台 Activity(`dumpsys activity`)。
- 写入对应结果目录,如 `runner/result/<plan>/<case>/fail_step_N/`。
- 由 `recording.py` 统一落盘,避免各处各写各的。

**验收**:故意让锚点不匹配,结果目录出现完整诊断包。

### RM-04 测试报告 (P1)

**建议方案**:在现有 `plan.json` 基础上输出 JUnit XML(便于 CI 解析)和单文件 HTML 报告(用例列表、通过率、失败截图内嵌)。

**验收**:CI 能读取 XML 展示结果;HTML 双击可看。

### RM-05 无头 CLI 批量运行 (P1)

**建议方案**:扩展 `runner/run_steps.py`:支持传入用例目录,逐个执行,汇总结果,以退出码表示成败(0 全过,1 有失败),不依赖 GUI。

**验收**:`python -m ... run <目录>` 可在无显示环境运行。

### RM-06 中文输入 (P1)

**现状**:`AdbClient.text()` 仅支持 ASCII,注释写"输入法方案暂未集成"。

**建议方案(二选一,建议先做 A)**
- A:ADBKeyboard 广播输入(`am broadcast -a ADB_INPUT_TEXT`),需要设备安装 ADBKeyboard。
- B:写剪贴板后粘贴,无需装 App,但各机型兼容性差异大。

**验收**:`input` 步骤能输入含中文的字符串。

### RM-07 用例参数化与重试 (P2)

**建议方案**:步骤里支持 `${变量}` 占位,变量来自用例级或命令行;步骤级 `retry` 字段,失败后按次数重试,降低偶发误报。

### RM-08 多设备并行执行 (P2)

**建议方案**:按设备 id 起多个 `StepRunner`,各自独立结果目录;`AdbClient` 已按设备 id 隔离,主要工作是调度与结果汇总。

### RM-09 跨平台适配 (P3)

**建议方案**:去掉 Windows 硬编码(字体 `Microsoft YaHei UI`、`D:/Python/Python311` 路径),字体与路径走配置或系统探测。

### RM-10 SIMD / C++ 加速 (P3)

**现状**:仅有 `docs/simd_acceleration.md` 的设想,无实现。
**建议**:没有 benchmark 数据证明瓶颈前不做。

### RM-11 分层自愈定位:局部模板匹配 + AI 兜底 (P1)

**背景与决策(2026-10-10)**
- 技术路线:**AI 生成脚本,确定性回放;只在定位失败时分层补救**。不采用"每步执行都让 AI 现场生成命令"——可复现性差、成本与耗时线性放大、失败时分不清是应用 bug 还是 AI 点错。
- 现有 `_check_start_condition`(`src/steps.py:411`)只比对整屏相似度且只告警不阻断,对弹窗、动画、时间文字敏感,**不能**作为"目标是否移位"的判据。保留其现有行为不变。

**三层链路**

```
执行 tap 前,先做"目标验证":
  第一层  在原坐标附近的小范围内匹配目标小图
          - 命中 → 按原坐标(或命中位置)点击,不调 AI
  第二层  原位置没命中 → 在全屏范围匹配目标小图
          - 命中 → 点击新位置,标记"自愈(模板)"
  第三层  全屏也没命中 → 用步骤意图调用 AI 重新定位
          - 必须经 vlm.verify 二次校验通过才点击,标记"自愈(AI)"
          - 校验不通过 → 步骤失败,走 RM-03 失败诊断
```

**目标小图由代码自动生成,不需要人工再截图**
- 不新增必填字段。录制或加载时,代码用已有的 `before_image`(点击前整屏图)和点击坐标 `x, y`,以坐标为中心裁剪 `crop_size`(默认 120x120,越界时贴边)作为目标模板。
- 因此**旧脚本无需改动即可使用**。
- 可选字段 `target_image`:步骤里显式提供小图时优先使用(用于自动裁剪效果不好的步骤)。非必填。
- 注意:input、keyevent、app_* 等非点击步骤不参与自愈。

**意图字段(非必填)**
- AI 兜底的意图优先取新增的可选字段 `intent`(录制时 AI 模式的原始自然语言查询自动写入),其次回退到 `desc`。
- 具体用哪个,以实现后的实际效果为准;新字段保持非必填,不影响现有用例与用户体验。
- 手动录制、`intent` 与 `desc` 都为空的步骤:**不允许触发 AI 兜底**,最多走到第二层。

**开关与配置**

全局默认写在 `config.yaml`:

```yaml
heal:
  mode: off            # off | template | ai   off=保持现状;template=只做模板重定位;ai=模板失败后再 AI 兜底
  crop_size: 120       # 自动裁剪目标小图的边长(像素)
  search_margin: 120   # 第一层在原坐标周围的搜索半径(像素)
  threshold: 0.85      # 模板匹配阈值
  ai_verify: true      # AI 结果是否必须经 verify 二次校验(建议保持 true)
```

用例级覆盖(需要支持的原因:不同用例对严格程度要求不同):
- 现有用例文件是裸 JSON 数组,没有用例级配置的位置。
- 方案:加载器同时兼容两种格式——旧格式(数组)和新格式(对象 `{"config": {"heal": {...}}, "steps": [...]}`)。旧格式视为无用例级配置,沿用全局值。
- 优先级:步骤级(可选,如 `"heal": "off"`)> 用例级 > 全局 `config.yaml`。
- 严格模式(CI):`heal.mode: off`,失败就是失败。

**留痕要求(必须做,否则会掩盖真实 bug)**
- 自愈成功的步骤在结果与报告(RM-04)中单独标记,不算纯通过;记录原坐标、新坐标、命中层级、相似度。
- 断言步骤(RM-01)不参与自愈,避免"自己找到答案再自己判对"。
- GUI 在回放日志里提示"建议更新脚本坐标",可选一键回写新坐标。

**实现要点**
- 新增 `src/heal.py`(或 `src/locate/heal.py`),封装三层逻辑;`StepRunner` 在 tap 前调用,不把逻辑塞进 `steps.py` 主循环。
- 模板匹配直接复用 `src/imgloc/`(`template` matcher),AI 兜底复用 `src/locate/pipeline.py`,不重复造轮子。
- 坐标换算统一使用 CR-02 收敛后的格子尺寸。
- 自动裁剪的目标图要避开纯色、低纹理区域(如空白背景),此类步骤跳过第一、二层,在日志提示"目标缺乏特征"。

**验收**
- `heal.mode: off` 时行为与现在完全一致。
- 人为把目标图标位置偏移后,`template` 模式能自动找到并点击,报告标记为自愈。
- `ai` 模式下,模板也失败时 AI 能重新定位;AI 结果校验不通过时步骤失败而不是硬点。
- 旧版裸数组用例无需修改即可加载并运行。

**待实现时验证的开放问题**
- 自动裁剪 120x120 对小图标、文字按钮是否足够区分,需要在真实用例(KOF 登录流程)上试。
- 游戏类画面有动画和粒子特效,模板阈值可能需要按用例调。
- `intent` 与 `desc` 谁更适合作为 AI 输入,以实测为准。
